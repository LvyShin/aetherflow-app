# 微信与支付宝账单导入

## 支持范围

- 微信支付和支付宝官方导出的 `.xlsx`、`.xls`、`.csv` 文件。
- 单文件最大 1MB，读取工作簿中的第一个工作表。
- 自动跳过表头前的声明、导出时间和空白行，最多扫描前 50 行。
- 识别交易时间、交易对方、商品说明、收/支、金额、支付方式、状态和交易单号。

## 导入流程

1. 用户在设置中心进入“导入数据”，选择本地账单文件。
2. `BillImportParser` 读取文件并转换为二维矩阵。
3. `header_detector` 定位真实表头并判断微信或支付宝渠道。
4. `bill_row_mapper` 逐行清洗金额、时间、账户和分类，无法解析的行形成问题说明。
5. 页面展示支出、收入、时间范围、重复数量及前 20 笔预览。
6. 用户确认后，流水模块通过单个 SQLite 事务批量写入。

文件在浏览器端解析，不上传到服务器。

导入数量按以下规则计算：

```text
有效导入数 = 原始数据行 - 已退款/关闭/失败/撤销/取消 - 不计收支 - 无法解析行 - 重复行
```

预览中的“过滤”表示官方账单里明确标记为退款、中性收支或 `/` 的行。它们不会进入消费和收入合计。

## 账户和分类

- 微信文件默认进入微信支付账户，支付宝文件默认进入支付宝账户。
- 支付方式明确包含银行卡时，进入招商银行卡账户。
- 分类由商户和商品文本推断，例如餐饮、交通、购物、医疗、薪资和理财。无法判断时使用“消费”或“收款”。

## 去重规则

每笔账单生成 SHA-256 指纹：

```text
渠道 | 原交易单号 | 交易时间 | 金额 | 收支类型 | 商户
```

数据库通过 `external_id` 唯一索引和导入前查询双重保障。同一文件重复导入、多个账期文件存在交集时，已有流水会作为重复项跳过。

## 当前限制

- 安全邮箱拉取依赖后续邮箱账户和同步配置，本阶段未接入。
- 原生“从微信/QQ分享导入”依赖 Capacitor 分享插件，本阶段使用系统文件选择。
- 退款、关闭、失败、撤销和取消状态暂不导入。
- 分类规则是本地启发式推断，导入后仍可在流水详情中修改。
